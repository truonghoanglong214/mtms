## 1. Domain Model & Business Invariants

### 1.1 Operating Expense Rules (`BR-FIN-07`)
1. **Category Restriction:**
   - Expenses must belong to a financial category with `category_group = 'OPERATING_EXPENSE'` (`OPEX_RENT`, `OPEX_UTILITIES`, `OPEX_SUPPLIES`, `OPEX_MARKETING`, `OPEX_MAINTENANCE`, `OPEX_OTHER` or custom active OPEX categories).
   - Any attempt to create an expense under other category groups (`CAPITAL_FLOW`, `INTERNAL_TRANSFER`, `DEBT_SETTLEMENT`, `REVENUE`) is rejected with `400 Bad Request` (`urn:mtms:error:invalid-expense-category`).
2. **Threshold & Abnormal Spending Alert (`review_flag`):**
   - Default alert threshold: `2,000,000 VND` (or branch-configured threshold).
   - If `amount >= threshold`: `review_flag = TRUE`. The UI displays an alert badge, and the Owner is flagged for special audit/review.
   - If `amount >= 500,000 VND`: An invoice / payment receipt (`evidence_file_id`) is strongly recommended or required.
3. **Payment Modes & Cash Subledger Linkage:**
   - **Mode A: Paid immediately (`is_paid = TRUE`):**
     - Must specify `payment_account_id` (Cash or Bank financial account belonging to the branch).
     - When transitioning to `CONFIRMED`:
       - Automatically posts an `OUTFLOW` entry to `mtms.cash_ledger_entries`:
         - `account_id = payment_account_id`
         - `category_id = category_id`
         - `source_type = 'MANUAL_EXPENSE'`
         - `source_id = expense.id`
         - `source_leg = 'MAIN'`
         - `amount = amount`
         - `signed_amount = -amount`
         - `memo = "Chi phí: " + category_name + " - " + reason`
         - `evidence_file_id = evidence_file_id`
       - Deducts `amount` from the financial account balance under a pessimistic row lock (`@Lock(LockModeType.PESSIMISTIC_WRITE)`).
       - Throws `400 Bad Request` (`urn:mtms:error:insufficient-account-balance`) if account balance is insufficient.
   - **Mode B: Unpaid / On credit (`is_paid = FALSE`):**
     - Automatically creates an open liability record in `mtms.payables`:
       - `source_type = 'MANUAL_PAYABLE'`
       - `source_id = expense.id`
       - `counterparty_label = reason` (or supplier/vendor name)
       - `original_amount = amount`
       - `paid_amount = 0`
       - `status = 'OPEN'`
     - Does not alter cash/bank accounts at creation. (Will be settled later via `P0-FIN-05`).
4. **Approval Lifecycle & Roles:**
   - Statuses: `DRAFT`, `CONFIRMED`, `VOIDED`.
   - `BRANCH_MANAGER`: Can create, update draft, and confirm standard expenses within permission scope.
   - `BRANCH_OWNER`: Can confirm flagged abnormal expenses (`review_flag = TRUE`) and void expenses.
5. **Voiding & Reversal Invariant:**
   - When a `CONFIRMED` paid expense is `VOIDED`:
     - Its linked cash ledger entry is marked `REVERSED` with an offsetting entry, restoring account funds.
     - The expense status becomes `VOIDED`.
   - When an unpaid expense is `VOIDED`:
     - Its linked payable is marked `CANCELLED`.
6. **TC-011 Idempotency:**
   - Expense creation and confirmation support `Idempotency-Key` headers. Duplicate requests return cached responses and prevent duplicate ledger debits.

## 2. Database Schema (Flyway V016)

```sql
-- 1. Branch Expense Alert Threshold Configurations
CREATE TABLE mtms.branch_expense_configs (
    branch_id UUID PRIMARY KEY REFERENCES mtms.branches(id),
    alert_threshold_amount NUMERIC(20, 2) NOT NULL DEFAULT 2000000.00,
    evidence_required_threshold NUMERIC(20, 2) NOT NULL DEFAULT 500000.00,
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- 2. Operating Expenses (OPEX Ledger)
CREATE TABLE mtms.expenses (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    branch_id UUID NOT NULL REFERENCES mtms.branches(id),
    expense_code VARCHAR(60) NOT NULL,
    expense_date DATE NOT NULL,
    category_id UUID NOT NULL REFERENCES mtms.financial_categories(id),
    amount NUMERIC(20, 2) NOT NULL CHECK (amount > 0),
    is_paid BOOLEAN NOT NULL DEFAULT TRUE,
    payment_account_id UUID REFERENCES mtms.financial_accounts(id),
    payable_id UUID REFERENCES mtms.payables(id),
    evidence_file_id UUID REFERENCES mtms.evidence_files(id),
    status VARCHAR(24) NOT NULL DEFAULT 'DRAFT' CHECK (status IN ('DRAFT', 'CONFIRMED', 'VOIDED')),
    review_flag BOOLEAN NOT NULL DEFAULT FALSE,
    reason TEXT NOT NULL,
    created_by UUID NOT NULL REFERENCES mtms.users(id),
    confirmed_by UUID REFERENCES mtms.users(id),
    confirmed_at TIMESTAMPTZ,
    voided_by UUID REFERENCES mtms.users(id),
    voided_at TIMESTAMPTZ,
    void_reason TEXT,
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    CONSTRAINT uq_expenses_branch_code UNIQUE (branch_id, expense_code),
    CONSTRAINT ck_expenses_payment_account CHECK (NOT is_paid OR payment_account_id IS NOT NULL)
);

CREATE INDEX idx_expenses_branch_date ON mtms.expenses (branch_id, expense_date);
CREATE INDEX idx_expenses_branch_status ON mtms.expenses (branch_id, status);
CREATE INDEX idx_expenses_category ON mtms.expenses (category_id);
CREATE INDEX idx_expenses_review_flag ON mtms.expenses (branch_id, review_flag) WHERE review_flag = TRUE;
```

## 3. REST API Specifications

### 3.1 Expenses API
- `GET /api/v1/branches/{branchId}/expenses`
  - Secured by `@branchAuth.hasBranchAccess(#branchId)`.
  - Query params: `status`, `categoryId`, `startDate`, `endDate`, `reviewFlagOnly` (boolean), `search`, `page`, `size`.
  - Response: `200 OK` paginated list of `ExpenseDto`.

- `POST /api/v1/branches/{branchId}/expenses`
  - Secured by `@branchAuth.hasBranchAccess(#branchId)`.
  - Supports `Idempotency-Key` header.
  - Body:
    ```json
    {
      "expenseDate": "2026-11-18",
      "categoryId": "uuid-financial-category",
      "amount": "2500000.00",
      "isPaid": true,
      "paymentAccountId": "uuid-financial-account",
      "evidenceFileId": "optional-uuid-evidence",
      "reason": "Hóa đơn tiền điện tháng 11/2026",
      "confirmImmediately": true
    }
    ```
  - Validation:
    - Category must belong to `OPERATING_EXPENSE`.
    - If `amount >= 2,000,000`, `review_flag` set to `true`.
    - If `isPaid == true`, `paymentAccountId` must not be null and belong to `branchId`.
  - Response: `201 Created` with `ExpenseDto`.

- `GET /api/v1/branches/{branchId}/expenses/{id}`
  - Detail of a single expense with category info, account info, creator/confirmer names, and linked cash ledger entry info.

- `POST /api/v1/branches/{branchId}/expenses/{id}/confirm`
  - Confirms a `DRAFT` expense.
  - Posts to `mtms.cash_ledger_entries` (if `isPaid`) or creates `mtms.payables` (if unpaid).
  - Response: `200 OK` with updated `ExpenseDto`.

- `POST /api/v1/branches/{branchId}/expenses/{id}/void`
  - Voids an expense.
  - Body: `{ "reason": "Nhập trùng hóa đơn" }`.
  - Reverses linked cash ledger entry (if was paid) or cancels payable (if unpaid).
  - Response: `200 OK` with voided `ExpenseDto`.

- `GET /api/v1/branches/{branchId}/expenses/config`
  - Get branch expense threshold configurations.
- `PUT /api/v1/branches/{branchId}/expenses/config`
  - Update alert thresholds (Requires `BRANCH_OWNER` or `SYSTEM_ADMIN`).

## 4. Error Codes & RFC 7807 Problem Details

| HTTP Status | Error Code (`type`) | Description |
|---|---|---|
| 400 Bad Request | `urn:mtms:error:invalid-expense-category` | Danh mục chi phí phải thuộc nhóm OPERATING_EXPENSE |
| 400 Bad Request | `urn:mtms:error:insufficient-account-balance` | Số dư tài khoản thanh toán không đủ để chi |
| 400 Bad Request | `urn:mtms:error:expense-already-confirmed` | Phiếu chi đã được xác nhận trước đó |
| 400 Bad Request | `urn:mtms:error:expense-already-voided` | Phiếu chi đã bị hủy trước đó |
| 404 Not Found | `urn:mtms:error:expense-not-found` | Không tìm thấy phiếu chi |
| 404 Not Found | `urn:mtms:error:financial-category-not-found` | Không tìm thấy danh mục chi phí |
| 404 Not Found | `urn:mtms:error:financial-account-not-found` | Không tìm thấy tài khoản thanh toán |
| 403 Forbidden | `urn:mtms:error:forbidden` | Người dùng không có quyền truy cập chi nhánh |
