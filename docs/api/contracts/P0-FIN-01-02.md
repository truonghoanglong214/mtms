## 1. Domain Model & Business Invariants

### 1.1 Category Taxonomy & Separation Rules (`BR-FIN-01`)
1. **Separation of Concerns:** All financial transactions belong to one of the following mutually exclusive groups:
   - `OPERATING_EXPENSE`: Day-to-day branch operating expenditures (Utilities, rent, cleaning, small maintenance). Affects managerial P&L.
   - `CAPITAL_FLOW`: Owner/investor equity transactions (`CAPITAL_CONTRIBUTION`, `CAPITAL_WITHDRAWAL`). **Never recorded as sales revenue or business expense**.
   - `INTERNAL_TRANSFER`: Cash movements between accounts within the same branch (Cash to Bank or Bank to Cash). **Zero net change in branch cash; zero effect on revenue and P&L (`TC-010`)**.
   - `DEBT_SETTLEMENT`: Payments to suppliers against existing payables (`mtms.payables`). Reduces cash and reduces liabilities; **never duplicated as operating expense (`TC-009`)**.
   - `REVENUE`: Cash and bank transfer receipts originated from confirmed daily revenue reports (`mtms.daily_revenue_reports`).
   - `PAYROLL`: Actual payroll cash disbursements. Reduces liabilities; not double-counted as period expense.
   - `OTHER`: Other non-operating adjustments.

2. **System Categories (`is_system = TRUE`):**
   - Core system categories are seeded and immutable regarding their group and flow direction. Users cannot delete system categories.
   - Custom categories created by users must belong to `OPERATING_EXPENSE`.

### 1.2 Cash & Bank Ledger Invariants (`BR-FIN-09`, `TC-010`, `TC-011`)
1. **Append-Only Immutability:**
   - Ledger entries (`mtms.cash_ledger_entries`) are never updated in place or physically deleted.
   - Corrections require an offsetting reversal entry (`status = 'REVERSED'`, referencing `reversal_of_id`).
2. **Double Posting Prevention (`TC-011`):**
   - Unique database constraint: `UNIQUE (account_id, source_type, source_id, source_leg)`.
   - Concurrent or repeated postings from the same origin leg (e.g., daily revenue cash leg, supplier payable payment leg) are strictly idempotent and cannot duplicate ledger records or balance changes.
3. **Pessimistic Balance Updating:**
   - Account balances (`mtms.financial_accounts.current_balance`) are updated within database transactions using `SELECT ... FOR UPDATE` row locks.
   - Each ledger entry captures an immutable `running_balance` snapshot immediately after posting.
4. **Internal Transfer Dual Legs (`TC-010`):**
   - An internal transfer atomically creates two ledger entries:
     - `OUTFLOW` on `from_account` with `source_leg = 'SOURCE'`.
     - `INFLOW` on `to_account` with `source_leg = 'DESTINATION'`.
   - Both legs reference the transfer record `mtms.internal_transfers.id` as `source_id` under category `TRF_INTERNAL`. Net P&L impact = 0 VND.

```sql
-- 2. Financial Accounts (Per branch)
CREATE TABLE mtms.financial_accounts (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    branch_id UUID NOT NULL REFERENCES mtms.branches(id),
    bank_account_id UUID REFERENCES mtms.branch_bank_accounts(id),
    account_name VARCHAR(160) NOT NULL,
    account_kind VARCHAR(16) NOT NULL CHECK (account_kind IN ('CASH', 'BANK')),
    currency CHAR(3) NOT NULL DEFAULT 'VND',
    current_balance NUMERIC(20,2) NOT NULL DEFAULT 0.00,
    status VARCHAR(24) NOT NULL DEFAULT 'ACTIVE' CHECK (status IN ('ACTIVE', 'INACTIVE')),
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    UNIQUE (branch_id, account_name),
    CHECK ((account_kind = 'CASH' AND bank_account_id IS NULL) OR (account_kind = 'BANK'))
);

CREATE INDEX idx_financial_accounts_branch ON mtms.financial_accounts (branch_id, account_kind);

-- 3. Internal Transfers (Cash <-> Bank within branch)
CREATE TABLE mtms.internal_transfers (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    branch_id UUID NOT NULL REFERENCES mtms.branches(id),
    from_account_id UUID NOT NULL REFERENCES mtms.financial_accounts(id),
    to_account_id UUID NOT NULL REFERENCES mtms.financial_accounts(id),
    amount NUMERIC(20,2) NOT NULL CHECK (amount > 0),
    business_date DATE NOT NULL,
    status VARCHAR(24) NOT NULL DEFAULT 'COMPLETED' CHECK (status IN ('COMPLETED', 'REVERSED')),
    note TEXT,
    evidence_file_id UUID REFERENCES mtms.evidence_files(id),
    created_by UUID NOT NULL REFERENCES mtms.users(id),
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    CHECK (from_account_id <> to_account_id)
);

CREATE INDEX idx_internal_transfers_branch_date ON mtms.internal_transfers (branch_id, business_date);

-- 4. Cash Ledger Entries (Append-only subledger)
CREATE TABLE mtms.cash_ledger_entries (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    account_id UUID NOT NULL REFERENCES mtms.financial_accounts(id),
    branch_id UUID NOT NULL REFERENCES mtms.branches(id),
    business_date DATE NOT NULL,
    entry_type VARCHAR(16) NOT NULL CHECK (entry_type IN ('INFLOW', 'OUTFLOW')),
    amount NUMERIC(20,2) NOT NULL CHECK (amount > 0),
    signed_amount NUMERIC(20,2) NOT NULL CHECK (signed_amount <> 0),
    running_balance NUMERIC(20,2) NOT NULL,
    category_id UUID NOT NULL REFERENCES mtms.financial_categories(id),
    source_type VARCHAR(48) NOT NULL CHECK (source_type IN (
        'DAILY_REVENUE', 'SUPPLIER_PAYMENT', 'INTERNAL_TRANSFER',
        'MANUAL_EXPENSE', 'CAPITAL_FLOW', 'PAYROLL_PAYMENT', 'MANUAL_ADJUSTMENT'
    )),
    source_id UUID NOT NULL,
    source_leg VARCHAR(24) NOT NULL DEFAULT 'MAIN',
    status VARCHAR(24) NOT NULL DEFAULT 'POSTED' CHECK (status IN ('POSTED', 'REVERSED')),
    reversal_of_id UUID REFERENCES mtms.cash_ledger_entries(id),
    memo TEXT,
    evidence_file_id UUID REFERENCES mtms.evidence_files(id),
    created_by UUID NOT NULL REFERENCES mtms.users(id),
    posted_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    -- TC-011: Source uniqueness prevents double posting
    UNIQUE (account_id, source_type, source_id, source_leg)
);

CREATE INDEX idx_cash_ledger_account_date ON mtms.cash_ledger_entries (account_id, business_date);
CREATE INDEX idx_cash_ledger_branch_date ON mtms.cash_ledger_entries (branch_id, business_date);
CREATE INDEX idx_cash_ledger_source ON mtms.cash_ledger_entries (source_type, source_id);
```

## 3. REST API Specifications

### 3.1 Financial Categories API
- `GET /api/v1/finance/categories`
  - Scoped to authenticated user.
  - Query params: `group`, `flowDirection`, `activeOnly` (default true).
  - Response: `200 OK` array of `FinancialCategoryDto`.
- `POST /api/v1/finance/categories`
  - Requires `SYSTEM_ADMIN` or `BRANCH_OWNER`.
  - Body:
    ```json
    {
      "categoryCode": "OPEX_ICE",
      "categoryName": "Chi phí mua đá bi",
      "description": "Chi phí mua đá viên bên ngoài bổ sung"
    }
    ```
  - Enforces: new user categories must belong to `OPERATING_EXPENSE` and `OUTFLOW`.

### 3.2 Financial Accounts API
- `GET /api/v1/branches/{branchId}/finance/accounts`
  - Secured by `@branchAuth.hasBranchAccess(#branchId)`.
  - Auto-initializes primary CASH account if none exists.
  - Response: `200 OK` list of accounts with `currentBalance`.
- `POST /api/v1/branches/{branchId}/finance/accounts`
  - Creates a new financial account (e.g. connecting a registered `branch_bank_account`).
  - Secured by `@branchAuth.hasBranchAccess(#branchId)`.

### 3.3 Cash Ledger API (`FE-P0-11`)
- `GET /api/v1/branches/{branchId}/finance/ledger`
  - Secured by `@branchAuth.hasBranchAccess(#branchId)`.
  - Query params: `accountId`, `categoryId`, `startDate`, `endDate`, `sourceType`, `page`, `size`.
  - Response: `200 OK` paginated ledger entries with `runningBalance`, `signedAmount`, `evidenceToken`.
- `POST /api/v1/branches/{branchId}/finance/transfers`
  - Executes internal transfer (`TC-010`).
  - Secured by `@branchAuth.hasBranchAccess(#branchId)`.
  - Header: `Idempotency-Key` supported.
  - Body:
    ```json
    {
      "fromAccountId": "uuid",
      "toAccountId": "uuid",
      "amount": "5000000.00",
      "businessDate": "2026-11-17",
      "note": "Nộp tiền mặt cuối ngày vào tài khoản Techcombank",
      "evidenceFileId": "optional-uuid"
    }
    ```
  - Validation:
    - `fromAccountId != toAccountId`.
    - `amount > 0`.
    - `fromAccount.currentBalance >= amount`.
  - Response: `201 Created` with transfer summary.
- `POST /api/v1/branches/{branchId}/finance/entries`
  - Direct ledger entry posting for capital injections/withdrawals or approved manual adjustments.
  - Secured by `@branchAuth.hasBranchAccess(#branchId)`.
  - Header: `Idempotency-Key` supported.
  - Body:
    ```json
    {
      "accountId": "uuid",
      "categoryId": "uuid",
      "entryType": "INFLOW",
      "amount": "20000000.00",
      "businessDate": "2026-11-17",
      "memo": "Chủ quán nạp tiền bổ sung vốn lưu động",
      "evidenceFileId": "optional-uuid"
    }
    ```
  - Response: `201 Created`.

## 4. Error Codes & RFC 7807 Problem Details

| HTTP Status | Error Code (`type`) | Description |
|---|---|---|
| 400 Bad Request | `urn:mtms:error:insufficient-account-balance` | Số dư tài khoản nguồn không đủ để thực hiện giao dịch |
| 400 Bad Request | `urn:mtms:error:invalid-transfer-accounts` | Tài khoản nguồn và tài khoản đích phải khác nhau và cùng thuộc chi nhánh |
| 400 Bad Request | `urn:mtms:error:invalid-category-group` | Danh mục tùy chỉnh phải thuộc nhóm OPERATING_EXPENSE |
| 404 Not Found | `urn:mtms:error:financial-account-not-found` | Không tìm thấy tài khoản tài chính |
| 404 Not Found | `urn:mtms:error:financial-category-not-found` | Không tìm thấy danh mục thu chi |
| 409 Conflict | `urn:mtms:error:duplicate-ledger-posting` | Bút toán đã được ghi nhận trước đó (TC-011) |
| 403 Forbidden | `urn:mtms:error:forbidden` | Người dùng không có quyền truy cập chi nhánh |
