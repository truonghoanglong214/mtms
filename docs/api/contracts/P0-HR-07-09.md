## 1. Domain Model & Business Invariants

### 1.1 Business Invariants (`BR-HR-06`, `TC-015`, `TC-016`, `TC-017`)
1. **Lập Phiếu Chi Trả Lương & Khớp Nối Sổ Quỹ (`P0-HR-07` / `BR-HR-06`):**
   - Phiếu chi lương (`payroll_payments`) ghi nhận số tiền thực chi cho từng dòng lương (`payroll_lines`).
   - Hỗ trợ chi trả từng phần (`partial payment`) hoặc tất toán toàn bộ (`paid_amount <= gross_salary`).
   - Ràng buộc: `amount > 0` và `amount <= (gross_salary - paid_amount)`. Nếu số tiền thanh toán vượt quá số dư lương còn nợ, hệ thống từ chối với lỗi RFC 7807 `400 Bad Request` (`urn:mtms:error:payroll-payment-exceeds-remaining`).
   - Khi thanh toán thành công:
     - Tự động cộng dồn `payroll_lines.paid_amount += amount`.
     - Cập nhật số tiền lũy kế đã chi của kỳ bảng lương `payroll_periods`.
     - Sinh một bút toán xuất quỹ `OUTFLOW` vào sổ quỹ tiền mặt/ngân hàng (`mtms.cash_ledger_entries`) qua `CashLedgerService.postLedgerEntry`:
       - `source_type`: `PAYROLL_PAYMENT`
       - `category`: `PAY_SALARY` ("Chi trả lương nhân viên", nhóm `PAYROLL`)
       - `source_id`: payment ID
       - `source_leg`: `'PAYMENT'`
       - `business_date`: `paid_on` (ngày thực chi)
       - `amount`: số tiền thanh toán
     - Khóa bi quan hàng tài khoản quỹ (`PESSIMISTIC_WRITE`), từ chối nếu số dư tài khoản quỹ không đủ chi (`urn:mtms:error:insufficient-funds`).

2. **Quy tắc Hạch toán Bất biến `TC-016` (Accrual vs Cash Flow):**
   - **Kỳ ghi nhận chi phí (P&L Accrual)**: Lương của tháng 11 (`month_start = 2026-11-01`) được ghi nhận chi phí vào báo cáo kết quả kinh doanh của tháng 11 khi bảng lương được phê duyệt.
   - **Kỳ phát sinh dòng tiền (Cash Outflow)**: Khi thanh toán thực tế vào ngày 05/12/2026 (`paid_on = 2026-12-05`), dòng tiền chi xuất quỹ ghi nhận vào ngày 05/12/2026.
   - **Bất biến `TC-016`**: Số dư quỹ tiền mặt/ngân hàng của tháng 11 **hoàn toàn không bị sửa đổi hồi tố**, và số dư quỹ tháng 12 giảm trừ chính xác bằng số tiền thực chi.

3. **Giao diện Phiếu lương & Bảo mật Quyền riêng tư (`P0-HR-08` / `FE-P0-23`):**
   - Nhân viên chỉ xem được phiếu lương (`Payslip`) của chính mình thông qua endpoint bảo mật `/my-payslips`.
   - Cấp Quản lý / Chủ quán có thể xem toàn bộ bảng lương và lịch sử chi trả của chi nhánh.

## 2. Database Schema (Flyway `V023`)

```sql
-- P0-HR-07 & P0-HR-08: Payroll Payments and Cash Ledger Linkage

CREATE TABLE mtms.payroll_payments (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    payroll_line_id UUID NOT NULL REFERENCES mtms.payroll_lines(id) ON DELETE CASCADE,
    account_id UUID NOT NULL REFERENCES mtms.financial_accounts(id),
    amount NUMERIC(20,2) NOT NULL CHECK (amount > 0),
    paid_on DATE NOT NULL,
    payment_method VARCHAR(20) NOT NULL DEFAULT 'BANK_TRANSFER' CHECK (payment_method IN ('CASH', 'BANK_TRANSFER')),
    status VARCHAR(20) NOT NULL DEFAULT 'POSTED' CHECK (status IN ('POSTED', 'REVERSED')),
    external_reference VARCHAR(160),
    evidence_file_id UUID REFERENCES mtms.evidence_files(id),
    ledger_entry_id UUID REFERENCES mtms.cash_ledger_entries(id),
    note TEXT,
    confirmed_by UUID REFERENCES mtms.users(id),
    created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE INDEX idx_payroll_payments_line ON mtms.payroll_payments(payroll_line_id);
CREATE INDEX idx_payroll_payments_account ON mtms.payroll_payments(account_id);
CREATE INDEX idx_payroll_payments_paid_on ON mtms.payroll_payments(paid_on);
```

## 3. REST API Specification

### 3.1 `POST /api/v1/branches/{branchId}/hr/payroll-lines/{lineId}/pay`
Chi trả lương cho một nhân viên cụ thể (thanh toán từng phần hoặc toàn bộ).

**Request Body:**
```json
{
  "accountId": "aa0e8400-e29b-41d4-a716-446655440001",
  "amount": 2500000.00,
  "paidOn": "2026-12-05",
  "paymentMethod": "BANK_TRANSFER",
  "externalReference": "UNC-20261205-001",
  "evidenceFileId": null,
  "note": "Chi trả lương đợt 1 tháng 11"
}
```

**Response `201 Created`:**
```json
{
  "id": "bb0e8400-e29b-41d4-a716-446655440002",
  "payrollLineId": "220e8400-e29b-41d4-a716-446655440002",
  "accountId": "aa0e8400-e29b-41d4-a716-446655440001",
  "accountName": "Ngân hàng Vietcombank CN Quận 1",
  "amount": 2500000.00,
  "paidOn": "2026-12-05",
  "paymentMethod": "BANK_TRANSFER",
  "status": "POSTED",
  "externalReference": "UNC-20261205-001",
  "ledgerEntryId": "cc0e8400-e29b-41d4-a716-446655440003",
  "note": "Chi trả lương đợt 1 tháng 11",
  "paidAmountAfter": 2500000.00,
  "remainingSalary": 250000.00,
  "createdAt": "2026-12-05T08:30:00Z"
}
```

### 3.2 `POST /api/v1/branches/{branchId}/hr/payroll-periods/{periodId}/bulk-pay`
Chi trả lương hàng loạt cho nhiều hoặc toàn bộ nhân viên chưa tất toán trong kỳ.

**Request Body:**
```json
{
  "accountId": "aa0e8400-e29b-41d4-a716-446655440001",
  "paidOn": "2026-12-05",
  "paymentMethod": "BANK_TRANSFER",
  "items": [
    {
      "payrollLineId": "220e8400-e29b-41d4-a716-446655440002",
      "amount": 2750000.00,
      "externalReference": "UNC-001"
    },
    {
      "payrollLineId": "330e8400-e29b-41d4-a716-446655440003",
      "amount": 3500000.00,
      "externalReference": "UNC-002"
    }
  ],
  "note": "Chi trả toàn bộ bảng lương tháng 11"
}
```

**Response `200 OK`:**
```json
{
  "totalPaidAmount": 6250000.00,

  "paymentIds": [
    "bb0e8400-e29b-41d4-a716-446655440002",

  ]

```

## 4. RFC 7807 Error Responses

| Mã lỗi HTTP | Type URI | Lý do |
| :--- | :--- | :--- |
| `400 Bad Request` | `urn:mtms:error:payroll-payment-exceeds-remaining` | Số tiền chi trả vượt quá mức lương còn nợ. |
| `400 Bad Request` | `urn:mtms:error:insufficient-funds` | Số dư tài khoản tiền mặt/ngân hàng không đủ để chi trả. |
| `400 Bad Request` | `urn:mtms:error:payroll-not-approved` | Bảng lương chưa được phê duyệt `APPROVED` không thể chi trả. |
| `404 Not Found` | `urn:mtms:error:payroll-not-found` | Không tìm thấy dòng lương hoặc kỳ bảng lương. |
| `403 Forbidden` | `urn:mtms:error:forbidden` | Người dùng không có quyền trên chi nhánh hoặc xem phiếu lương của người khác. |
