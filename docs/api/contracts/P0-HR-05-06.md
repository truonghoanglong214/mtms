## 1. Domain Model & Business Invariants

### 1.1 Business Invariants (`BR-HR-04`, `BR-HR-05`, `BR-HR-10`, `TC-013`, `TC-014`, `TC-015`, `TC-017`)
1. **Engine tính lương đa lát thời gian (`TC-013` - Midmonth Wage Slices):**
   - Đối với nhân viên hưởng lương theo giờ (`HOURLY`):
     - Quét toàn bộ dòng chấm công đã duyệt (`status = 'APPROVED'`) trong tháng.
     - Với mỗi ca làm việc, xác định chính sách lương có hiệu lực tại ngày làm việc đó (`work_date`).
     - $\text{Lương ca} = (\text{approved\_minutes} \div 60) \times \text{rate\_amount(work\_date)}$.
     - Lương cơ bản trong tháng: $\text{base\_salary} = \sum \text{Lương ca}$.
     - Lưu chi tiết phân rã từng lát ngày vào `calculation_snapshot` (ví dụ: 50h mức 22.000đ/h và 50h mức 25.000đ/h $\rightarrow 2.350.000$ VND - `TC-013`).

2. **Quy đổi lương tháng theo ngày công chuẩn (`TC-014` - Monthly Wage Proration):**
   - Đối với nhân viên hưởng lương theo tháng (`MONTHLY`):
     - Xác định mức lương tháng và số ngày công chuẩn (`standard_workdays`, mặc định 26 ngày công).
     - Tổng hợp số ngày công thực tế đã duyệt (`payable_workdays`) từ bảng chấm công.
     - $\text{base\_salary} = \text{rate\_amount} \times (\text{payable\_workdays} \div \text{standard\_workdays})$.
     - Ví dụ: 7.000.000đ với 13 ngày công trên 26 ngày chuẩn $\rightarrow 3.500.000$ VND (`TC-014`).

3. **Điều chỉnh thủ công có ký hiệu (`payroll_adjustments`):**
   - Các khoản cộng (`signed_amount > 0`): `ALLOWANCE`, `BONUS`, `OTHER`.
   - Các khoản trừ (`signed_amount < 0`): `PENALTY`, `ADVANCE_DEDUCTION`, `OTHER`.
   - $\text{gross\_salary} = \text{base\_salary} + \text{adjustments\_total}$ (ràng buộc $\text{gross\_salary} \ge 0$).

4. **Phân bổ chi nhánh chính cuối tháng (`TC-015`):**
   - Bảng lương kỳ tháng của chi nhánh chỉ bao gồm các nhân viên có chi nhánh chính (`is_primary = true`) tại chi nhánh đó vào **ngày cuối cùng của tháng** (`monthEnd`).
   - Nếu nhân viên chuyển chi nhánh giữa tháng, chi nhánh công tác cuối tháng gánh toàn bộ chi phí lương của tháng đó.

5. **Phê duyệt bảng lương & Kiểm soát Cấm tự duyệt (`TC-017` / `HR-INV-02`):**
   - Bảng lương ban đầu ở trạng thái `DRAFT`.
   - **Chỉ Chủ quán (`branch.owner`) hoặc Quản trị viên (`system.admin`)** mới có thẩm quyền phê duyệt bảng lương của chi nhánh.
   - Quản lý cửa hàng (`branch.manager`) bị từ chối phê duyệt bảng lương (`403 Forbidden` `urn:mtms:error:forbidden` hoặc `urn:mtms:error:self-approval-denied`).
   - Khi bảng lương được duyệt `APPROVED`:
     - Trạng thái chuyển sang `APPROVED`, ghi nhận `approved_by` và `approved_at`.
     - Toàn bộ bảng lương bị khóa vĩnh viễn, ngăn chặn tính lại hoặc thêm/xóa điều chỉnh.
     - Lưu trữ snapshot JSONB bất biến: `policy_snapshot` và `calculation_snapshot`.

## 2. Database Schema (Flyway `V022`)

```sql
-- P0-HR-05 & P0-HR-06: Payroll Periods, Lines, and Adjustments

CREATE TABLE mtms.payroll_periods (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    branch_id UUID NOT NULL REFERENCES mtms.branches(id),
    month_start DATE NOT NULL,
    revision INTEGER NOT NULL DEFAULT 1 CHECK (revision > 0),
    is_current BOOLEAN NOT NULL DEFAULT TRUE,
    status VARCHAR(24) NOT NULL DEFAULT 'DRAFT' CHECK (status IN ('DRAFT', 'APPROVED', 'SUPERSEDED', 'VOIDED')),
    total_gross_salary NUMERIC(20,2) NOT NULL DEFAULT 0.00 CHECK (total_gross_salary >= 0),
    total_base_salary NUMERIC(20,2) NOT NULL DEFAULT 0.00 CHECK (total_base_salary >= 0),
    total_adjustments NUMERIC(20,2) NOT NULL DEFAULT 0.00,
    employee_count INTEGER NOT NULL DEFAULT 0 CHECK (employee_count >= 0),
    note TEXT,
    approved_by UUID REFERENCES mtms.users(id),
    approved_at TIMESTAMPTZ,
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    UNIQUE (branch_id, month_start, revision),
    CHECK (EXTRACT(DAY FROM month_start) = 1)
);

CREATE UNIQUE INDEX uq_payroll_period_current ON mtms.payroll_periods(branch_id, month_start) WHERE is_current;

CREATE TABLE mtms.payroll_lines (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    payroll_period_id UUID NOT NULL REFERENCES mtms.payroll_periods(id) ON DELETE CASCADE,
    employee_id UUID NOT NULL REFERENCES mtms.employees(id),
    expense_branch_id UUID NOT NULL REFERENCES mtms.branches(id),
    rate_type VARCHAR(16) NOT NULL CHECK (rate_type IN ('HOURLY', 'MONTHLY')),
    approved_minutes INTEGER NOT NULL DEFAULT 0 CHECK (approved_minutes >= 0),
    payable_workdays NUMERIC(7,2) NOT NULL DEFAULT 0.00 CHECK (payable_workdays >= 0),
    base_salary NUMERIC(20,2) NOT NULL DEFAULT 0.00 CHECK (base_salary >= 0),
    adjustments_total NUMERIC(20,2) NOT NULL DEFAULT 0.00,
    gross_salary NUMERIC(20,2) NOT NULL CHECK (gross_salary >= 0),
    paid_amount NUMERIC(20,2) NOT NULL DEFAULT 0.00 CHECK (paid_amount >= 0),
    policy_snapshot JSONB NOT NULL DEFAULT '{}'::jsonb,
    calculation_snapshot JSONB NOT NULL DEFAULT '{}'::jsonb,
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    UNIQUE (payroll_period_id, employee_id),
    CHECK (paid_amount <= gross_salary)
);

CREATE TABLE mtms.payroll_adjustments (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    payroll_line_id UUID NOT NULL REFERENCES mtms.payroll_lines(id) ON DELETE CASCADE,
    adjustment_code VARCHAR(50) NOT NULL,
    signed_amount NUMERIC(20,2) NOT NULL CHECK (signed_amount <> 0),
    explanation TEXT NOT NULL,
    approved_by UUID REFERENCES mtms.users(id),
    created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE INDEX idx_payroll_adjustments_line ON mtms.payroll_adjustments(payroll_line_id);
```

## 3. REST API Specification

### 3.1 `GET /api/v1/branches/{branchId}/hr/payroll-periods`
Lấy danh sách các kỳ bảng lương theo năm/tháng.

**Query Parameters:**
- `year` (int, optional)
- `status` (`DRAFT`, `APPROVED`, optional)

### 3.3 `POST /api/v1/branches/{branchId}/hr/payroll-periods/generate`
Tính toán lại toàn bộ bảng lương tháng (`recalculate`) từ dữ liệu chấm công mới nhất.

**Request Body:**
```json
{
  "monthStart": "2026-11-01"
}
```

---

### 3.4 `POST /api/v1/branches/{branchId}/hr/payroll-lines/{lineId}/adjustments`
Thêm khoản điều chỉnh lương (phụ cấp, thưởng, phạt, tạm ứng).

**Request Body:**
```json
{
  "adjustmentCode": "BONUS",
  "signedAmount": 500000.00,
  "explanation": "Thưởng đạt chỉ tiêu doanh số"
}
```

---

### 3.5 `DELETE /api/v1/branches/{branchId}/hr/payroll-adjustments/{adjId}`
Xóa khoản điều chỉnh lương (chỉ khả dụng khi bảng lương ở trạng thái `DRAFT`).

---

### 3.6 `POST /api/v1/branches/{branchId}/hr/payroll-periods/{id}/approve`
Chủ quán phê duyệt chốt bảng lương kỳ tháng.

**Quy tắc kiểm soát bảo mật `TC-017`:**
- Bắt buộc kiểm tra: Người gọi API phải có vai trò Chủ quán (`BRANCH_OWNER`) hoặc Quản trị viên (`SYSTEM_ADMIN`).
- Quản lý cửa hàng (`MANAGER`) bị chặn `403 Forbidden` (`urn:mtms:error:self-approval-denied` hoặc `urn:mtms:error:forbidden`).

**Response `200 OK`:** Bảng lương chuyển trạng thái `APPROVED` và bị khóa vĩnh viễn.

## 4. RFC 7807 Error Responses

| Mã lỗi HTTP | Type URI | Lý do |
| :--- | :--- | :--- |
| `400 Bad Request` | `urn:mtms:error:invalid-payroll-data` | Dữ liệu tháng sai định dạng, lương âm. |
| `403 Forbidden` | `urn:mtms:error:self-approval-denied` | **`TC-017`**: Quản lý không có thẩm quyền phê duyệt bảng lương. |
| `403 Forbidden` | `urn:mtms:error:forbidden` | Người dùng không có quyền truy cập chi nhánh. |
| `404 Not Found` | `urn:mtms:error:payroll-not-found` | Không tìm thấy kỳ bảng lương hoặc dòng lương. |
| `409 Conflict` | `urn:mtms:error:payroll-already-approved` | Bảng lương đã được phê duyệt không thể tính lại hoặc sửa đổi. |
